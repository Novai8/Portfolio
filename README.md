# ISYS-inspired Administrative Quality Review Automation

> **Independent portfolio prototype. Not an official ISYS system and not connected to ISYS internal systems.**

An **ISYS-inspired Administrative Quality Review Automation** prototype built with **n8n, Gmail, OpenAI, and Supabase** using fictional/sample data.

The project demonstrates how an administrative document-review process can be turned into a structured automation that receives reports, processes supporting documents, performs an AI quality review, stores the result, and sends follow-up communication when required.

## Demo

**Video demonstration:** https://youtu.be/rCsg1Lq3xc0

The video shows the workflow from incoming Gmail report through document processing, AI review, Supabase case storage, decision-making, and follow-up email generation.

## What it demonstrates

```text
Gmail
  ↓
Intake
  ↓
Document Detection / Routing
  ↓
Document Extraction
  ↓
AI Quality Review
  ↓
Structured Review Result
  ↓
Supabase Case Database
  ↓
Decision
  ├── Follow-up required → AI email writer → Gmail → Update case
  └── No follow-up → Complete case → Mark Gmail processed
```

### Review checks

- Case and report information
- Queue and report type
- Submission date and deadline
- Missing information and documents
- Contradictions between sources
- Invoice status
- Customer requirements
- Urgency and escalation
- Recommended action
- Whether follow-up communication is required

The AI is instructed to **use available evidence only**, avoid guessing, keep email and attachment evidence separate, and explicitly flag missing or contradictory information.

## Database

The prototype uses a Supabase table named `cases` to track review results and workflow state.

The record includes case/report identifiers, quality findings, missing information, invoice status, urgency, recommended action, email state, Gmail message ID, processing state, document status, and overall business status.

`id` is generated by Supabase, while `gmail_message_id` comes directly from Gmail.

## Key design principles

- **Evidence-first:** never invent or guess unavailable information.
- **Source separation:** email content and attachment content are treated as separate sources.
- **Contradiction detection:** conflicting values are flagged instead of silently choosing one.
- **Structured output:** review results are normalized into predictable fields before database storage.
- **Conditional automation:** follow-up communication is generated only when the review determines it is required.
- **Traceability:** case and processing statuses are stored in Supabase.
- **Safe demonstration data:** all names, case numbers, documents, and values are fictional/sample data.

## Limitations

This is a portfolio prototype rather than a production deployment. It does not connect to ISYS systems, use ISYS internal data, or represent an official ISYS workflow. Production use would require organization-specific business rules, authentication, security controls, monitoring, data-retention policies, and human review requirements.
