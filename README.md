# ISYS-inspired Administrative Quality Review Automation

> **Independent portfolio prototype. Not an official ISYS system and not connected to ISYS internal systems.**

This project is an **ISYS-inspired Administrative Quality Review Automation** prototype built with n8n, Gmail, OpenAI, and Supabase using fictional/sample data.

## What it demonstrates

The automation simulates an administrative quality-review workflow:

```text
Gmail
  ↓
Intake
  ↓
Document Detection / Routing
  ↓
Document Extraction
  ↓
AI Quality Review
  ↓
Structured Review Result
  ↓
Supabase Case Database
  ↓
Decision
  ├── Follow-up required → AI email writer → Gmail → Update case
  └── No follow-up → Complete case → Mark Gmail processed
```

### Review checks

- Case and report information
- Queue and report type
- Submission date and deadline
- Missing information and documents
- Contradictions between sources
- Invoice status
- Customer requirements
- Urgency and escalation
- Recommended action
- Whether follow-up communication is required

The AI is instructed not to invent or guess missing information and to treat email content and attachment content as separate sources.

## Test scenarios

| Case | Scenario | Expected outcome |
|---|---|---|
| ISYS-73104 | Complete case | Ready, no follow-up |
| ISYS-59283 | Missing invoice | Missing Information, follow-up |
| ISYS-84621 | Date contradiction | Needs Review, follow-up |
| ISYS-91462 | Serious discrepancy | Escalation Required, urgent follow-up |

All case information is fictional/sample data.

## Database

Supabase table: `cases`

The case record tracks review findings, document status, invoice status, email status, processing status, Gmail message ID, and overall case status.

`id` is generated by Supabase. `gmail_message_id` comes directly from Gmail.
